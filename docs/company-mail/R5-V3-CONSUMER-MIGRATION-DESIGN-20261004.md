## Trust origin and propagation

Three hashes have distinct meanings: v3 `binding_sha256` is selection identity; `observation_sha256` is canonical SHA256 of **all receipt fields except itself**, including binding hash and complete ordered envelope; manifest/preparation/batch pins hash **serialized file bytes**. Never substitute one for another.

Trusted origin is the authorized executor/controller that selects the exact reviewed checkout and absolute producer, invokes capture, and receives the complete successful return object through its owned channel. It computes `observation_digest` itself from that complete object, checks the returned seal, writes exclusive receipt bytes, reads those bytes through descriptors and confirms the complete digest before publication. It must not derive authority by reopening an arbitrary candidate and copying its `observation_sha256`. Hashing a forged receipt and signing it yourself is not independent provenance.

Use a small versioned pin bundle, held outside candidate/source/dependency writable trees. Proposed exact fields: `schema_version=1`, `policy=r5_selected_observation_pins_v1`, `run_id`, `source_commit`, `source_root`, `selected_binding_version=3`, `producer={path,sha256,version}`, `observations={slot:{receipt_path,receipt_byte_sha256,observation_sha256,context}}`. Preparation slots are before/after × default/race-r5protocol; external-runtime admission slots are default/race-r5protocol. Reject missing/extra/duplicate slots and swapped phases, roots or contexts. Digests may coincide for identical complete observations; do not manufacture inequality.

Authority comes from a controller-held expected **bundle byte hash** passed explicitly into the consumer (or authenticated controller memory), never from a colocated `.sha256`, the candidate, or an env value supplied by that candidate. One cooperating trusted executor is sufficient; a second human or a signing infrastructure is not required. Across machines, transfer bundle and its expected hash through the parent's authenticated evidence channel; if that channel is unavailable, fail closed. Controller compromise/quiescence is a stated limitation, not solved by adding self-hashes.

Preparation owns four captures itself, so compute and persist pins from successful owned returns before using comparisons. Its new preparation schema includes version, bundle reference/hash and per-slot references; `validate_wire` requires the independently propagated preparation byte pin, then bundle pin and all receipts, seals, slots and binding equalities. Parent runner carries returned evidence paths/hashes/run ID only to current children; sanitize new v3 selectors/pin variables out of frozen children too. No new observation pin originates from `binding_sha256`.

External capture receives `--selected-binding-version 3`, bundle path plus independently supplied bundle hash, explicit absolute Go/cache/modulecache. Verify **both** candidate envelopes and contexts before any live producer call. Then call v3.validate with each bundle pin. Its returned fresh observation is a different evidence object: retain it in a fresh admission-evidence directory and publish a new controller-origin pin bundle for those fresh returns; never overwrite input receipts/pins or use the old observation pin for the new return. If bindings drift, retain rejection and publish no admitting manifest. Success produces runtime schema/policy v3 (`r5_external_dependency_runtime_v3`), with selected version, admitted bundle reference/hash, producer path/hash and receipt byte hashes. Publisher independently pins final manifest bytes. Runtime v3 load checks explicit caller opt-in and manifest/bundle pins; observe verifies each admitted complete envelope before ordinary archive/source/descriptor comparisons. Initial validation is live; later checks are static metadata-envelope plus live filesystem observations, exactly as scoped above.

Do not trust a changed bundle because a candidate manifest contains its new hash. Only a manifest authenticated by its controller-supplied expected byte hash may delegate trust to its immutable bundle reference. Batch's externally pinned contract may carry the already trusted runtime and bundle pins transitively; recapture hashes are equality evidence, not new trust origins. No v2 manifest accepts selected-v3 receipts, and no v3 manifest accepts v2 or selected-v1. Batch v1 remains v2-only; add an explicit batch-v2 policy/schema for runtime-v3, retaining identical cases and lifecycle. Component bridge accepts runtime-v3 only with explicit version selector and all existing manifest/executable checks.
