## 第一轮：四项独立缺口

### EXEC-01：完整 SMTP 策略替换

原 PATCH 解码把遗漏和 null 转为零值，部分请求会清空其他策略字段，仍写设置、成功审计并清缓存。新的输入解码要求两个布尔字段与五个列表字段都显式出现且非 null；列表中的 null 同样拒绝。明确的 false 和空列表仍是有效操作。GET 回显携带的 `updated_at` 保留兼容，标为弃用并忽略；OpenAPI 新建独立的完整替换输入 schema。

固定回归通过实际 JWT/router/handler 和有状态 FakeStore 观察 HTTP 响应及三类副作用。36 个叶子在原生产代码上为 **15 PASS / 21 FAIL / 0 SKIP**，修复后为 **36 PASS**；加上原 SMTP policy 用例，相关回归为 **37 PASS**。这是 HTTP 与应用边界验证，不把 FakeStore 说成 PostgreSQL 事务执行。

作者源：测试基线 `6e406057f57b05e08881067c14452a428a0006c9`，修复 `3b1084c80954f24caa81792416da4a0b78287aa6`，修复 tree `1c7c1747b361d1734127546f6635c73539d38174`。root 复审输入、所有七个字段、原客户端及 OpenAPI，接受限定修复。

### EXEC-02：邮箱生命周期冲突后的意图复核

原移交／转换表单在写入冲突后只显示 toast；后台 props 更新可能把旧属主和旧原因重新绑定到新 revision。现在首次编辑固定所见快照，冲突、未知写结果和后台变化保持锁定；必须显式成功读取同 tenant、同 mailbox 的唯一有效新快照，再勾选已核对，才可再次提交。读取期间的会话、邮箱和编辑变化使旧结果失效。保留理由输入、同属主排除及父组件原同步 action 锁。已确认写成功但后续列表刷新失败时，显示已完成并禁止重放。

固定 21 项在原生产代码上 **3 PASS / 18 FAIL / 0 SKIP**，候选与五个已有相关文件共 **103 PASS / 0 FAIL / 0 SKIP**。初次测试错误地把相同 revision 配成不同 owner，后来固定成一致快照，并在原生产代码重新跑同一最终测试，原失败日志保留。初始化已兼容无 window 的预渲染环境；两条 POST 路径保持显式，原 AST 客户端采集器能识别。

### EXEC-03：截短 BDAT 不得成功接收或持久化

原 fork 忽略 `io.Copy` 的返回字节数；客户端半关闭写端时，短 EOF 可返回 nil error，导致截短 LAST 块收到 `250 queued` 并创建原件与 message/durable job，非 LAST 块也可错误收到 `250 Continue`。修复比较实际字节数与声明长度，短块按 UnexpectedEOF 拒绝，先以原 `ErrDataReset` 关闭后台消费管道，再沿用 reset/join 清理。

固定真实 TCP 用例覆盖 durable / non-durable、完整单块、多块、零长块、二进制正文及同连接后续命令同步。固定测试 SHA256 为 `cb10738391418bcdd8ff405e2a57cfba9df6bae002b11a2548339f2cba82fb34`。基线 **10 PASS / 8 FAIL / 0 SKIP**；最终固定回归 **18 PASS**，整个 `internal/smtp` **118 PASS**，整个 SMTP fork **86 PASS**，均无失败或跳过。

第一候选曾把后台错误直接改成 UnexpectedEOF，旧完整回归暴露 `ErrDataReset` 契约被破坏；最终修正保留原错误，旧测试未改。fork 独立历史 `go 1.13` 模块执行遇到 synctest 计时器语义失败，最终从实际生产主模块运行同一完整 fork 测试。Go 1.25.7，`-mod=readonly -race -p 1 -count=1 -timeout=120s` 不放宽。

最终作者候选 `a01ed323bff2e4d5441d7d235878b460248ee5bd` / tree `16065b9a8ab97ef6a4b0535caf946d61c5712d46`。root 与 backend 独立静态复核，backend 执行最终三组，transport 再解析原始日志，均接受。最早私有终端的冷编译 OOM 日志已经丢失，只作过程说明；已保留的构造失败、真实基线、初版兼容失败和最终日志才列入证据清单。

定义校验拒绝主题、纯文本正文、HTML 正文及声明的选项中的 NUL；渲染校验拒绝用户变量和三种身份字段中的 NUL，包括未被正文引用的值。交叉审查进一步发现模板持久化 Name 的遗漏，补入 SaveMailTemplate 的既有前置名称验证。因此保存、发布、预览和实际出站构造都经过相应边界。正常 Unicode、false-like 文本、正文换行及原大小限制保持。
