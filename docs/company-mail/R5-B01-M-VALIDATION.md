## 2. 原版实际问题

在原始 commit 导出的副本上，仅覆盖与最终相同的 `parser_resource_test.go`，七个顶层测试得到六个失败、一个通过：

| 原版失败 | 实际观察 |
|---|---|
| 不同原件并发 | 12 个被屏障阻塞的不同 key 同时打开，峰值 12；64 MiB LRU 预算只约束保留缓存，不限制在途读取 |
| 延迟 Read 超时 | 虚拟时钟超过 30 秒，任务仍等待 reader；人为释放后原版返回成功并写入缓存 |
| 延迟 Get 超时 | 对象 Get 在共享截止以后返回，原版仍解析并缓存 |
| 无进展读取 | 连续 101 次 `(0,nil)` 后返回有效邮件，原版总计读取 103 次并把结果缓存 |
| reader 与 error 同时返回 | 原版保留错误，但没有关闭已经返回的 reader |
| 排队容量与期限 | 四个未完成 Get 存在时，第五个原件仍被打开，没有准入边界 |

原版通过的对照为：取消一个同-key 等待者不会取消其他等待者的共享解析。该语义保留。六个失败测试并非六项已确认生产事故。

## 3. 实现

`Parser` 新增实例内四个并发许可。不同 key 的共享任务在调用对象 Get 前申请许可，许可一直持有到读取、MIME 解码、摘要/缓存提交结束；所有返回路径释放许可。同 key 继续由现有 singleflight 合并，不为每个等待者占许可；缓存命中不排队，singleflight 入口再次检查缓存以避免旧 lookup 引发重复打开。

沿用共享解析的独立 30 秒上下文，将许可等待包含在同一预算内；单个调用者取消只退出自己的等待。准入后、对象返回后、读取后、解码后与缓存写入前都检查共享上下文，超时结果不进入缓存。

新增内部 `source.go`，对象返回 reader 后即安排取消关闭，正常/错误退出与取消回调通过同一个 `sync.Once` 关闭 reader。Get 同时返回 reader 与 error 时也会关闭；已取消的读取不会再调用 Get。

读取包装保留 `MaxBytes+1` 的超限探测，校验非法读取计数，拒绝连续 100 次无进展返回；真实进展重置空读计数。数据与 EOF 同时返回仍保留数据，普通读取错误或取消不返回部分内容。包装不提升 WriterTo/ReaderFrom，避免快速复制入口绕过检查。现有原件大小、parts 限制、摘要与附件 ID 算法没有改变。

上下文取消回调的 stop 不代表回调已完成；关闭操作由 `sync.Once` 协调，不把 stop 当成等待。参考 Go 官方 [context.AfterFunc](https://pkg.go.dev/context#AfterFunc) 与 [io.Reader](https://pkg.go.dev/io#Reader) 文档。

## 5. 微基准与代价

同一小型合成 multipart 原件、同一机器 Apple M3 Max，原 commit 与候选分别执行三次、每次 1000 次迭代，未启用 race。记录的是中位数，不是吞吐量 SLA 或性能改善证明。

| 场景 | 原版 | 候选 | 分配变化 |
|---|---|---|---|
| 缓存命中 Document | 935.7 ns/op | 917.8 ns/op | 均 1080 B/op、16 allocs/op |
| 不同 key 冷 Document | 89718 ns/op | 99913 ns/op | 66380 → 67117 B/op，332 → 340 allocs/op |

本组样本冷解析有约 11% 时间开销，绝对约 10 微秒，缓存命中分配不变。新增准入、上下文与关闭协调以该开销换取资源保护，不宣称整体提速。小样本调度噪声、真实大邮件、S/M/L 基准、全进程 RSS、部署负载仍未测量；不关闭 P0-100。

## 6. 保证边界及未验收范围

- 四个许可是每个 Parser 实例的在途加载/解码上限，不是全进程上限，也不是总堆内存上限。companymail 与 mailindex 各有实例；直接调用 ParseBounded 的入站路径不受该许可控制，既有单消息界限保持。
- 排队有超时，但本批不限制 HTTP 请求数量或全部等待 goroutine 数量；缓存后的 HTML 净化/投影不纳入四许可，不据此声称全链资源已封顶。
- Get 必须响应 context，Close 必须能打断其并发 Read，才能及时结束 I/O。任意实现同时忽略二者不能强制杀死；保留其许可避免继续无界启动替代读取。同步 MIME CPU 解码不可被强制抢占，完成后的超时检查只能拒绝结果。
- 不改变内容授权、数据库事务、SQL、迁移、消息期限政策、Go module、npm lockfile、前端或公开 OpenAPI。B01-K PG 并发、完整 PG HTTP、浏览器、DNS/SSE、真实对象后端及生产投递尚未验收。
