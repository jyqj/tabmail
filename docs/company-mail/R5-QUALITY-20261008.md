QUALITY-09 是有界恢复尝试。元数据删除和入队仍为既有非原子流程，不保证崩溃、未知提交或未返回 key 的恢复；入队失败须继续处理。保守补交可能沿用原规则增加 attempts，重试上限未变。5 秒预算依赖底层端口遵守 context；未将这些限制表述为完整 P3 验收。

QUALITY-10 的原固定 19 个控制由 **11 PASS / 8 FAIL → 19 PASS**；后加“导航尚未确认仍保持关闭”和“显式重新选择可以打开”两个控制，在旧产品上单独执行均失败，其余 19 个因该诊断命令过滤而跳过。最终完整 21 个新控制及相关九文件 **192 PASS / 0 FAIL / 0 SKIP**。实际 Workspace、ReceivedFolder、MessagePane 保留首次不在本页的深链接、进行中／失败的刷新、不同视图和会话边界；确认同列表中曾见邮件消失才关闭正文并清理选择。最终 committed-state 通知通过完整 TypeScript 和零警告定向 lint，后端 lane 独立审查 ACCEPT。
