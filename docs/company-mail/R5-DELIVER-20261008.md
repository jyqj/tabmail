### SMTP 累计接收预算与最终确认

每条实际 TCP 连接累计最多接收 **1 MiB** 原始字节，包括 TLS 握手和密文；发送的 MIME 正文不消耗这项入站预算。连接重建获得独立预算，原命令 deadline、取消、关闭和 watcher 回收保持。该上限是本应用资源策略：合法但累计回复超过预算的服务器同样会被拒绝；它不是单行长度限制，也不声明所有 SMTP 对端必然兼容。

原固定 79 叶包括真实 loopback TCP 各阶段单行/多行洪泛、direct/relay/implicit TLS/STARTTLS、200 收件人的累计回复、正常多收件人和超过 1 MiB 的发送正文。首候选实际为 78 PASS / 1 FAIL：bufio 将缺少最后换行的 `250` 片段交给 textproto，后者错误视为成功。原失败和测试字节保留，再以独立新增五叶固定截断 `354/450/550`，验证正文发送前必须停止，最终不完整负码不能进入确定拒绝的错误链，也不得转投第二个 MX。

修复在 setup 阶段保留底层预算错误，在发送阶段用固定 4097 字节的明文尾部环检查 textproto 实际消费位置是否有结束 LF。最终 DATA 不完整时保留 `ErrOutboundUncertain`；已完整确认的 `250` 后 QUIT 故障保持成功。独审另构造真实 TLS 1.2 对照：完整已认证的最终 `250` 在预算内结束，紧贴的 close_notify 超限，确认仍有效。该控制在公开旧产品和候选均通过，原初始诊断保留，最终 v2 保证每条 SMTP 行不超过 512 字节。
