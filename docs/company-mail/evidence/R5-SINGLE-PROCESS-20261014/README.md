## 执行方式与边界

正式 PG 门禁只有一次原命令：

```sh
go test -json -race -count=1 -timeout=180s ./...
```

没有 matrix、分片、`-run` 选集、重试或新增 skip。原证据检查器及 mandatory 清单
未修改。Go 本身仍按原语义执行各包；180 秒是 Go 测试运行预算，不含整条 CLI 的
全部编译/包调度时间。CI 的独立 PG job 仍为 20 分钟。

测试设施优化：

1. PostgreSQL 测试包的 TestMain 拥有一个只初始化一次、禁止连接的迁移模板；
   每个测试获得不同的独立数据库，仍通过正式 `postgres.New/Migrate` 打开，
   每次测试清理自己的库，套件结束清理模板。没有生产启动快速通道。
2. 新控制验证模板与空库冷迁移的列、约束、索引和迁移账本相同；验证两份副本互不
   污染、禁止连接标志、失败初始化不发布、取消/关闭后不再初始化和清理归属。
   [PostgreSQL 16 的 TEMPLATE/连接规则](https://www.postgresql.org/docs/16/sql-createdatabase.html)
   是这套测试设施使用的数据库机制。
3. 沿用原有 `r5ParallelFreshDB` 精确名单与两路准入上限，只增加核对过的独立数据库
   用例。仍在同一个测试二进制内，子用例、真实时钟窗口、锁等待观察和断言不变。
   内部包用例保持串行，未增加进程或扩大准入并发数。
4. 一次性 PG 测试库使用 1 GiB tmpfs；显式检查 `fsync`、`full_page_writes`、
   `synchronous_commit` 均为 on。没有修改生产存储配置，也没有关闭这些设置。
   **这不是磁盘掉电耐久性或原 M 性能基准验收**。其他 backend 协议门禁仍使用原存储。
5. 既有 PG/UI 探针的依赖安装在私有外部目录，临时链接并精确清理，避免 npm 自带的
   无关 Go 文件混入 `./...`；不删除依赖文件或过滤 Go 包。

| 一次性测试库方式 | 每次创建＋打开/迁移＋删除平均 |
|---|---:|

| 磁盘模板独立副本 | 101 ms |
| tmpfs 空库逐次迁移 | 179 ms |
| tmpfs 模板独立副本 | 16 ms |

模板、tmpfs 单独组合仍曾撞到包预算；初次进程内并行接线又暴露重复 Parallel 调用和
内部/外部测试包边界错误。这些均已修正，原失败报告保留，不以之后的成功抹去。
最终沿用原两路准入机制，不绕过它，也不缩短真实期限。
