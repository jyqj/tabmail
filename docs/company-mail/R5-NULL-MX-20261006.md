# 直投 null MX 限定修复

2026-10-06。仅记录 R5-P6-090 的并行 WIP 进展。

## 固定源码与行为

基线为 PR53 head `9f2982d8366fabded56945991218a69cd715e1b8`、tree `41b83783e2419ea6fb560e8435e6ec10b18c0951`。独立验收的代码／测试候选 tree 为 `19877df9f5c06d6c8b84d1373214b2db1d7c8652`；交付仅再增加本报告和 TODO 追加记录。

原实现丢弃 MX preference，将唯一 `{Pref:0, Host:"."}` 传给普通直投会话；去掉尾点后得到空 host 和 `:25`。基线离线 session spy 实测一次会话调用，错误没有永久拒绝标记；独立 fake-store 实测结果为 Temporary／code0。

- 有效 null MX：仅唯一 preference-0、exchange `.` 的记录返回 `textproto.Error{Code:556, Msg:"5.1.10 Recipient domain does not accept mail (null MX)"}`。错误链保留该标记，现有收件人分类器据此落 Permanent／556；没有任何 session 调用或地址回退。依据 [RFC7505 第3节及4.1节](https://www.rfc-editor.org/rfc/rfc7505.html#section-3)。
- 畸形 root RRset：非零 preference、重复 root 或 root 与真实 MX 混用，全部在会话前返回普通临时错误，不回退域名、不尝试真实 MX。这是本批明确选择的保守无效响应策略；不将其称作 RFC 规定的永久 null-MX 拒绝。
- 普通 MX 顺序、host 去尾点、收件人／MIME／requireTLS 参数、空成功结果的原隐式域名路由、MX 重试、DNS 错误原因、取消、SMTP 4xx／5xx 和最终回复不确定性保持。空成功结果控制不证明真实无 MX／NXDOMAIN DNS 策略已经正确。

导出的 `DeliverDirect` 和 adapter API 不变；生产 wrapper 将标准 `net.Resolver.LookupMX` 和原 `deliverDirectMX` 传入私有逐调用 seam。测试注入实际 `net.MX` 记录后经过同一生产归一化与编排；没有全局可变 hook。relay、SMTP session、recipient classifier、store、迁移和依赖未改。
