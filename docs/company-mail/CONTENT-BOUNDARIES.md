# 公司邮件内容边界重构

基于 `main@b54a3a2b29ca25d170704e0685628605e6aa010a`。该版本已经包含域名开通、公司／邮箱发送策略、模板版本撤销、发送内容投影及 SubmissionService；本轮不重新实现这些能力，也不修改已发布迁移。

## 本轮落地

```text
router / RegisterCompanyRoutes（装配）
  ├─ CompanyHandler：公司、成员、邮箱、模板管理及运维
  ├─ CompanyMailHandler：员工邮件、草稿、发送回执 HTTP 适配
  │    ├─ companymail.Service：正文、原件、附件、回复／转发
  │    └─ submissions.Service：原子提交与草稿消费（保持原实现）
  └─ MailboxEventHandler：按当前阅读权限追赶持久化事件
```

删除旧 MessageHandler 中转层。HTTP 适配不解析 MIME、不直接读取对象；应用服务只接受 Actor 和不可变资源 ID，不接收 HTTP request 或客户端对象 key。管理处理器不再依赖员工读信、草稿及发送内容接口。Repository 的生产聚合仍保留，具体消费者使用 DraftWorkspace、AttachmentRepository、SubmissionReceipts、SubmissionContentReader、DeliveryRecovery 等小接口。

`GetWorkMessage` 在数据库事务内刷新有效成员与权限，检查公司、精确邮箱 ID 和 `CanRead`，并投影与列表相同的个人 seen/starred 状态。内部原件 key 只供应用服务使用，返回正文 DTO 时移除。不存在通过地址重新解析到另一个邮箱的路径。

## 回执不等于正文授权

| 资源 | 授权 |
| --- | --- |
| 发送回执列表／详情 | 当前公司内，本人提交，或来自当前可读邮箱；保留现有范围与字段 |
| 已发送正文、附件清单、已发送附件下载 | 当前公司内，对原发件邮箱仍具有阅读权；保留域名 allowlist 与邮箱过期检查 |
| 上传工作区附件 | 继续沿用已有作者＋当前发送权，或已关联发送任务＋当前阅读权的规则 |
| 入站正文、原件、附件 | 当前成员对请求中的精确邮箱仍有阅读权，且消息确实属于该邮箱 |
| 邮箱事件订阅 | 首次访问和每次追赶均重新检查当前 `CanRead`；管理权不是阅读权 |

历史提交者失去阅读权后仍可查看操作回执，但不能据此读取完整正文或已发送附件。仅发送授权也不能隐式读取公司邮箱历史。正文查询、附件清单、附件下载使用同一严格 SQL scope；不可见内容统一返回 404，不泄露其是否存在。此处没有新增最小回执 DTO：现有回执仍含主题、收件人和投递状态，不应描述为完全脱敏回执。

已上传工作区文件不是已发送信件的授权凭证：保留其既有访问规则不允许读取其他附件、正文或发送内容。已经开始的 HTTP 原件下载无法撤回已交付字节；本轮不承诺跨数据库与对象流的线性化撤权。

## 内容和附件处理

正文／入站附件解析限制为 25 MiB 原件；上传与已上传附件下载限制为 20 MiB。读取前检查授权，下载前校验 ready、非负且有上限的声明大小、SHA-256 和实际长度；损坏、截断、多余字节或未完成对象不能作为成功下载返回。校验失败时关闭读取器，不输出部分成功正文。

上传保持 reserve → object put → finish 的已有握手。对象写入失败不调用 finish；finish 失败不返回 ready，也不在提交结果不确定时贸然删除对象。遗留 reservation 仍交由原有留存／恢复机制处理。文件名清理统一处理路径分隔符、控制字符、`.` 与 `..`。

回复使用 Reply-To 优先，Reply-All 排除自身并去重，不携带 BCC；转发分别验证源邮箱阅读权和目标邮箱发送权，并为附件创建当前作者工作区引用。本轮不改变草稿版本、幂等键、逐收件人账本和投递重试语义。

## 验证与发布

新增测试覆盖授权前禁止对象读取、精确公司／邮箱绑定、作者撤权后回执与正文分离、共享邮箱列表／详情个人状态、管理角色事件订阅撤权、附件校验／关闭／上传握手及回复地址规则。架构测试检查依赖方向而非文件行数；既有 PostgreSQL race、模板策略、浏览器收发、生产镜像与契约检查继续运行。

运行方式：

```sh
go test -race -count=1 ./...
python3 scripts/check_contract_drift.py
(cd web && npx tsc --noEmit && npm test && npm run lint && npm run build)
```

数据库测试必须配置 `TABMAIL_TEST_DB_DSN`；没有数据库时的 skip 不等于验证成功。具体执行结果与工作流链接记录在 PR。新增只读 source evidence workflow 提供该 PR head 的 tracked-source 快照，不包含 Git 凭据、运行数据或对象存储。

无需新增数据库迁移或数据回填。切换此内容策略时必须替换／停止旧 API 实例，否则旧实例仍可能按历史提交者授权读取正文；回滚到旧 API 会重新放宽权限，不应作为无风险回退。SMTP 与 worker 事务路径本轮未改动。

## 明确未包含

本轮不是全方案完成：已发送内容仍是 outbound_jobs 的投影，尚未建立独立于任务保留期的邮件资产；模板停止新使用与紧急撤销的进一步治理、稳定入站附件 ID、公司管理页面拆分、离职预览等继续作为后续工作。不改变三层角色和现有管理层级保护，不代替生产 DNS、真实公网投递或备份恢复验收。
