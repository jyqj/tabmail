## 2. 实测问题与修复

| 问题 | 修复与证据 |
|---|---|
| Get/Delete/Exists 直接拼接 root 与 key；Put 只有词法检查 | 四个入口复用 canonical 相对路径检查与 `os.Root`。原版可以对测试对象根外的邻接夹具读取、写入或删除；修复后全部拒绝。所有根外夹具也只位于该测试的 TempDir 内，不触碰真实主机文件。 |
| 父目录 symlink 可在写入途中替换 | 临时文件、发布及目录同步均通过目录句柄/根限定 API；保留创建目录句柄用于失败清理。确定性 Read callback 将测试父目录替换成根外链接，并提供同名临时诱饵；修复不修改外部夹具或诱饵，原件不变且移动后的临时文件被清理。 |
| 声明 size 被忽略 | 非负 size 要求准确长度；最多多读一字节判断超长，避免 `size+1` 溢出。`-1` 保留明确未知长度流语义，其他负数拒绝。短源、超长、虚假零长度、nil reader 均不覆盖原件。 |
| Get/Delete/Exists 忽略取消 | 入口检查取消，读取前后检查上下文；`io.Copy` 也经过 Read，避免提升 os.File.WriteTo 后绕开检查。已经取消的操作不打开/删除对象。 |
| 连续无进展读取和错误流 | 100 次连续 `(0,nil)` 拒绝；真实进展重置预算；非法计数拒绝。数据与 EOF 同时返回仍保留完整数据，失败临时文件清理。 |
| 目录/叶子链接可被当作对象，相对配置受 chdir 影响 | Blob 必须是 regular file；禁止目录和叶子 symlink 对象。初始化把配置目录固定为绝对路径，新目录 0700、新文件 0600，不改现有目录权限。根内的父目录相对 symlink 仍有合法回归。 |

保留已有完整写入 → 文件 Sync → Close → 原子 Rename → 祖先目录 Sync 的发布顺序。声明长度核对在 Rename 前完成，失败不通过截断旧文件实现覆盖。并发读/写测试确认读者只见完整旧对象或完整新对象。

实现直接使用仓库已声明 Go 1.25.7 的标准库能力，无依赖升级。依据：[Go 1.25 的 Root 方法](https://go.dev/doc/go1.25)、[os.Root 的语义和边界](https://go.dev/src/os/root.go)。这些文档仅支持 API 选择，不替代本仓库实测。

## 4. 兼容、限制和未完成

Keys 现在必须是规范相对 slash 路径：空值、`.`、父目录、冗余分隔符、反斜杠及绝对路径拒绝。既有手工叶子 symlink 不再视为对象；存量非规范键或手工链接需在部署前只读清点，不自动迁移或删除。正常内容寻址 key 和上传 key 不变。调用方传入 size=0 现在明确表示空对象；需要未知长度必须传 -1，不能继续依赖旧后端忽略参数。

`os.Root` 不是对抗特权本地主体的完整沙箱：配置根及其属主是可信部署边界，不阻止硬链接、挂载点或管理员更换整个配置根。每次操作打开并关闭根句柄，不引入无人释放的长期句柄。先检查 regular file 再打开不宣称防止任意恶意本地主体制造设备/FIFO 竞争。路径安全的实测范围为本机 Unix 文件系统；Windows 和生产 Linux 文件系统行为未运行验收。

取消是操作/读取/发布前的决策检查，不撤销已经发布或删除的结果。任意 Reader 忽略上下文且永不返回，不能被强制杀死；调用者保有输入流的 Close 所有权。Rename 后目录 Sync 失败仍可能已发布：返回错误但不抢删对象，继续由既有恢复/对账协议处理，不承诺任何错误都意味着磁盘完全未变。

本批增加路径和类型检查，有额外系统调用，未提供生产吞吐或性能无回归结论。未知长度 -1 不引入新的全局容量政策；应用原有邮件/附件限额继续负责上层大小限制。

未修改 SQL、迁移、Go module、npm lockfile、OpenAPI、前端、S3 后端或 rawobject 引用协议。未运行 B01-K 六组真实 PG、PG HTTP journey、浏览器、远端 CI、断电故障注入、真实 S3、生产清理或部署。此前数据库启动拦截未尝试换入口重做。
