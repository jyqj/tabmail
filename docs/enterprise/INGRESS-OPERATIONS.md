# 入站运维工作台与可核对重试

基线：已发布 PR #7，`a60e4f2488840cda7b242719da23d477df5ea671`。
分支：`feat/ingress-operations-console`，独立叠加于 `feat/durable-ingress-recovery`。
本轮不导入此前未发布的公司前端/出站补丁，不修改工作流、冻结迁移或默认部署配置。

## 债务与本轮处理

| 债务 | 本轮处理 |
| --- | --- |
| 入站恢复只有 API，页面只能看聚合状态 | `/admin/ingest` 接上逐邮箱状态、失败原因、带理由和确认的恢复操作 |
| `dead` 同时表示旧任务和有账本的搁置任务 | 新检查接口返回 `recovery_managed`、`can_retry`、阻断原因；旧任务不提供重试按钮 |
| 分别查询任务和目标可能得到不同恢复周期的数据 | 元数据和目标在一个只读 repeatable-read 快照中返回 |
| 操作员看过的任务可能已被另一个操作员恢复过 | 新界面总是发送 `observed_updated_at`，后端持锁校验；过期快照返回409且不修改任务/审计 |
| 旧页面忽略请求错误、共享缓存、每敲一个字就查数据 | 独立捕获的会话/无共享缓存；显式应用筛选；错误时不展示旧详情或操作按钮 |
| 请求迟到、账号切换、网络失败后自动重放会误操作 | 账号边界重建页面、取消读取；POST不自动刷新凭据或重放；所有结果均重新核查状态 |
| 恢复理由限制字符数但旧4KiB请求限制拦截正常中文 | 增加到16KiB有界请求，保留2000 Unicode字符限制；实际Router测试验证1800个中文字符完整审计 |
| 状态英文与页面统计含义不清 | 新工作台中英双语；明确“当前页”统计、“本地入库”和“预计字节数”语义 |

## 界面使用

仅平台 `super_admin` 的交互式账号可使用。公司管理员、普通员工、API Key均不得读取跨公司收件记录。
前端在挂载请求前检查会话角色；服务器的真实用户状态和权限检查仍为最终边界。
公司工作台和普通邮箱阅读权限没有因此扩大。

打开 `/admin/ingest`，按状态、接收来源、完整信封收件人筛选。点击“查看恢复详情”，核查不可变目标邮箱ID、公司ID、失败原因以及已完成/未完成目标。
只有服务器快照明确允许恢复时，才出现理由、确认框和提交按钮；成功目标没有再次发送、修改目标或删除原文的入口。
旧任务无账本、账本异常、已经处理中的任务都有明确不可恢复原因。

提交后所有结果均使当前详情失效并重新读取。409表示已有新状态，需要重新核查；网络错误意味着结果未知，不等于事务回滚。
页面不会自动再次POST。会话到期或权限撤销时需要重新登录；本运维入口刻意不复用旧HTTP客户端的自动刷新/重放。
普通令牌轮换也会重建本页检查状态：对有副作用的运维操作，应重新核查，而不是保留旧确认。

## 新增/扩展 API

`GET /api/v1/admin/ingest/jobs/{id}`：返回 `data: IngressInspection`，同时包含任务状态、更新时间、目标列表和恢复资格。
不存在返回404；存在但没有账本的旧任务返回200且不可重试，避免把“旧任务不可安全重放”误解为请求故障。
不返回原文、存储路径、校验摘要、claim token或用户凭据。`expected_bytes`是接受时的元数据；不会调用对象存储验证当前文件存在。
列表和检查接口均返回 `Cache-Control: no-store`。

原 `POST /api/v1/admin/ingest/jobs/{id}/retry` 增加可选字段：

```json
{"reason":"存储故障已修复并核查原文","observed_updated_at":"2026-01-01T00:02:00.123456Z"}
```

值来自刚读取的检查接口，不是客户端时钟。比较和恢复在同一行锁事务中完成；即便任务再次失败回到dead，旧周期的理由/确认也不能重用。
缺少该字段的旧API客户端仍按PR #7规则处理，因此不能声称所有外部客户端都已强制使用乐观校验。
审计只记录已经提交的恢复；审计失败会回滚。此变更不扩大重试范围，不改目标、不改原文，不新增数据库迁移。

## 验证与剩余边界

新增真实PostgreSQL测试：一致读取、竞争操作员单次恢复、旧周期拒绝、审计失败回滚、旧任务/未知任务/空版本。
新增完整Router测试：平台/公司管理员/员工/匿名/API Key区分，no-store，格式错误/冲突/Unicode理由。
新增前端测试：真实fetch参数、捕获会话、无自动POST重放、筛选/分页、确认与理由、旧任务解释、读取失败清除旧内容、账号切换和迟到响应、中英界面。
另以Go反射核对新TypeScript DTO字段；验证实际OpenAPI整合后的路由和请求字段。字段检查不等于完整生成SDK。

本轮不解决容量有界的死信处置、原文孤儿清理、自动退信、服务登录恢复、旧整站会话债务或未发布出站恢复；Issue #6仍不关闭。
不做真实邮箱发送、DNS修改、部署或main合并。当前快照可读不代表原文必然健康；恢复请求提交不代表已投递完成。
实际本地/远端测试结果以该PR绑定的源码提交记录为准，不借用PR #7或文档提交的CI。
